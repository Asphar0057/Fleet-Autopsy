## Order of use
1. Before 11:30, ask your campus host whether pre-written prompts and steering files are allowed. Hacking officially starts at 11:30.
2. At 11:30: create the repo, connect it to GitHub through Kiro, copy `.kiro/steering/` into it, and copy `layouts/` to `public/layouts/`. Install fonts: `npm i @fontsource/instrument-serif @fontsource/geist @fontsource/geist-mono`.
3. Open Kiro in Spec mode and paste the part of `PROMPT_1_sim-core.md` below the line.
4. Read the generated requirements, design, and tasks. If they are bloated, ask for a trim before you start tasks (each task you run costs credits).
5. Before the first task: note your credit count, then check it again after one task so you know the real cost.
6. Commit after every task.

## The layouts
All three were generated by script and checked: the floor is one connected region, every pod, station, and charger has a reachable floor neighbor, and no floor cell is a dead end. Legend: `#` wall, `.` floor, `p` pod slot, `S` station, `c` charger. Endpoints are entered only as a goal and never traversed.

They were also run in a throwaway Python simulation (`reference/pibt_reference.py`) using the rules in the prompt: 5 seeds × 2,000 ticks at the recommended and max robot counts gave 0 collisions, every robot delivering, and no long idle spells. The first version of the rules deadlocked; three fixes (blocked-aware distance maps, yielding waiters, nearest-robot station reservation with a clean hand-off) are written into the prompt. The reference is a prototype, not your Kiro implementation, so your own health test is the real proof.

- **pocket-dc**: small, for tests and fast checks.
- **fulfillment-block**: the hero layout for the demo and benchmark.
- **chokepoint**: two one-cell doors and baffles that force a loop. Jams show up fast.
